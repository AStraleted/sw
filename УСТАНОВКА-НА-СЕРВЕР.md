# Как выложить SQULED Studio в интернет

Пошагово: от покупки домена до работающего сайта с https. Весь путь занимает около часа,
из них большая часть — ожидание, пока домен «пропишется».

---

## Шаг 1. Купить сервер (VPS)

Нужен самый простой: **1 ядро, 1–2 ГБ памяти, 10 ГБ диска, Ubuntu 24.04**. Этого хватает с запасом:
сайт почти ничего не считает сам, вся нагрузка на стороне API.

**Где брать (Россия, оплата картой РФ):**

| Хостинг | Цена от | Примечание |
|---|---|---|
| [Timeweb Cloud](https://timeweb.cloud) | ~200 ₽/мес | проще всего для первого раза, всё по-русски |
| [Selectel](https://selectel.ru) | ~250 ₽/мес | надёжнее, чуть сложнее панель |
| [Рег.ру](https://reg.ru) | ~200 ₽/мес | здесь же можно сразу взять домен |

**Если платить зарубежной картой:** [Hetzner](https://hetzner.com) (~4 €/мес, Германия) или
[Vultr](https://vultr.com) (~5 $/мес).

> Где именно стоит сервер, важно: от России до Германии задержка около 40 мс, это незаметно.
> Но если ваш API-сервис блокирует российские адреса, берите сервер за рубежом.

При создании выберите **Ubuntu 24.04** и добавьте SSH-ключ, если он у вас есть. Если нет —
хостинг пришлёт пароль root на почту.

## Шаг 2. Купить домен

| Где | Цена от | Зона |
|---|---|---|
| [Рег.ру](https://reg.ru) | 199 ₽/год | .ru |
| [Timeweb](https://timeweb.com/ru/services/domains/) | 219 ₽/год | .ru |
| [Namecheap](https://namecheap.com) | ~$10/год | .com, .io |

Домены `.ru` дешевле и требуют паспортные данные. `.com` дороже, но оформляется за минуту.

**Привязка домена к серверу.** В панели управления доменом найдите раздел «DNS-записи»
и добавьте две записи типа **A**, указав IP-адрес вашего сервера:

```
A    @      123.45.67.89
A    www    123.45.67.89
```

Адрес сервера хостинг показывает в панели. Изменения расходятся по интернету от 15 минут
до нескольких часов — можно сразу идти дальше, а потом вернуться.

## Шаг 3. Подключиться к серверу

Откройте терминал на своём компьютере (в Windows — PowerShell) и введите:

```bash
ssh root@123.45.67.89
```

Подставьте свой IP. При первом подключении ответьте `yes` и введите пароль.

## Шаг 4. Установить всё необходимое

Скопируйте блок целиком и вставьте в терминал:

```bash
apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs nginx unzip
node -v
```

Последняя команда должна показать `v22.x`.

## Шаг 5. Загрузить проект

Распакуйте архив на своём компьютере, затем **из папки с проектом** выполните:

```bash
scp -r squled-studio root@123.45.67.89:/opt/
```

Либо загрузите архив через файловый менеджер хостинга и распакуйте на сервере:

```bash
cd /opt && unzip squled-studio.zip
```

## Шаг 6. Настроить

```bash
cd /opt/squled-studio
npm run setup
```

Мастер задаст вопросы. Отвечайте так:

- **API-токен** — ваш ключ от сервиса
- **Порт** — `8787`
- **Открыть доступ из сети** — `нет` (наружу смотрит nginx, а не сам сайт)
- **Разрешить всем регистрироваться** — решайте сами; для закрытого доступа `нет`
- **Сайт по https** — `да`

Затем откройте `.env` и впишите данные администратора:

```bash
nano .env
```

```
ADMIN_LOGIN=squledAD
ADMIN_PASSWORD=ваш-новый-пароль
```

Сохранить: `Ctrl+O`, `Enter`, выйти: `Ctrl+X`.

> **Важно:** пароль, который вы присылали в переписке, считайте скомпрометированным.
> Поставьте здесь другой, а этот больше нигде не используйте.

## Шаг 7. Запустить как службу

Чтобы сайт поднимался сам после перезагрузки:

```bash
useradd -r -s /bin/false squled
chown -R squled:squled /opt/squled-studio
cp deploy/squled.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now squled
systemctl status squled
```

Должно быть написано `active (running)`.

Полезные команды на будущее:

```bash
systemctl restart squled    # перезапустить
journalctl -u squled -f     # смотреть, что происходит
```

## Шаг 8. Настроить nginx и https

```bash
cp deploy/nginx.conf /etc/nginx/sites-available/squled
nano /etc/nginx/sites-available/squled
```

Замените во всех местах `example.com` на ваш домен. Сохраните и выполните:

```bash
ln -s /etc/nginx/sites-available/squled /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default
apt install -y certbot python3-certbot-nginx
certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru
nginx -t && systemctl reload nginx
```

Certbot спросит почту и предложит перенаправлять http на https — соглашайтесь.
Сертификат бесплатный и продлевается сам.

## Шаг 9. Закрыть лишнее

```bash
ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw --force enable
```

Теперь снаружи открыты только порты 22, 80 и 443, а сам сайт на 8787 доступен лишь изнутри сервера.

## Готово

Откройте `https://ваш-домен.ru` и войдите под логином администратора.
Первым делом — **Настройки → Профиль → Сменить пароль**.

## Выдача тарифов

1. Человек регистрируется на сайте и сообщает вам свой логин.
2. Он переводит оплату и пишет вам в Telegram.
3. Вы открываете **Администрирование**, находите его в списке, нажимаете «…» → **Выдать тариф** →
   нужный тариф и срок.
4. Кредиты и доступ появляются у него сразу, перезаходить не нужно.

Там же можно создать аккаунт самому (кнопка «Создать») — логин и пароль скопируются в буфер,
останется отправить их человеку.

## Резервные копии

Все данные лежат в одной папке. Делайте копию раз в неделю:

```bash
tar czf /root/squled-backup-$(date +%F).tar.gz -C /opt/squled-studio data
```

Автоматически каждую ночь — добавьте строку в `crontab -e`:

```
0 4 * * * tar czf /root/squled-$(date +\%F).tar.gz -C /opt/squled-studio data && find /root -name 'squled-*.tar.gz' -mtime +14 -delete
```

## Обновление проекта

```bash
systemctl stop squled
cd /opt && cp -r squled-studio/data /root/data-backup
# скопировать новые файлы поверх, папку data не трогать
chown -R squled:squled /opt/squled-studio
systemctl start squled
```

## Если что-то не работает

| Что видите | Что делать |
|---|---|
| «Сервер недоступен» в браузере | `systemctl status squled` — служба должна быть `running` |
| 502 от nginx | сайт не запустился: `journalctl -u squled -n 50` |
| Ответ приходит целиком, а не по словам | в nginx потерялась строка `proxy_buffering off` |
| Не открывается по домену | DNS ещё не разошлись, проверьте: `dig ваш-домен.ru` |
| «Сервис отклонил API-ключ» | проверьте `API_TOKEN` в `.env` и перезапустите службу |
| Кончилось место | `du -sh /opt/squled-studio/data/*` — скорее всего, разрослись загруженные файлы |
